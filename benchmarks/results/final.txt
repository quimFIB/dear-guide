Final acceptance run
====================

2026-08-29, after every fix. Same generator, same machine, same command shape
as the baseline in `../raw.json`. Raw data: `final/`.

Compared op-for-op against the tool before any of this work:

    improved  > 1.15x    67
    unchanged            50
    regressed < 0.87x     0
    ------------------------
    compared            117

Slowest ratio 0.96x, on a 0.027 ms measurement.


--- Exponents --------------------------------------------------------------

                    before   after
    Graph.validate    3.03    1.95
    dg check          3.03    1.85
    dg brief            --    1.91
    dg context        ~2.0    1.85
    dg render         ~2.0    1.87
    dg find <word>    ~2.0    0.49   <- now dominated by process start-up

Nothing is cubic. `dg find` is sub-linear because at these sizes it is mostly
the 244 ms interpreter+import and 106 ms JSON parse, not the store.

    dg check          132,509 ms ->  12,455 ms

    dg find <word>     11,769 ms ->     353 ms
    dg find <miss>     23,314 ms ->     538 ms

    dg render           6,239 ms ->   6,152 ms

Measured separately at 10,000 vertices:

    Graph.validate        988.9 s ->    3.1 s
    dg check              ~17 min ->   16.6 s
    dg brief            (skipped) ->   27.6 s
    dg find quokka         48.7 s ->    0.54 s
    dg serve payload   (unusable) ->    3.2 s   (139.8 s at 1,000 before)


--- What is left, and it is no longer graph work --------------------------

`dg render` barely moved (6,239 -> 6,152 ms) and `dg context` only 1.2x. Those
two, and the 96% of `dg serve`'s payload that is not traversal, are all the
same thing: **building and formatting output**, not answering questions about
the graph. Every graph question underneath them is now milliseconds.

So the next round, if there is one, is about what these commands *produce* --
how much text, how much JSON, for whom -- and not about how fast they compute
it. That is a design question, and a better place to have stopped than another
pass with the profiler.
