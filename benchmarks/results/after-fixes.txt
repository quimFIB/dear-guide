The cubic term is gone from all three. Everything remains quadratic, which is
what fixes A and D address and neither of those was implemented.


--- What got slower --------------------------------------------------------

Nothing. Across 117 ops comparable at matching (op, size, layer), the lowest
ratio is 0.97x:

  tasks.blocked_ids    1000  library   14.22 ms -> 14.50 ms   0.98x
  find.prose_absent    5000  library  11304.7 ms -> 11544.0 ms 0.98x
  find.above_sink      1000  library   96.07 ms -> 98.41 ms   0.98x
  query.lenses_build   1000  library    0.95 ms ->  0.98 ms   0.97x
  active_edge.first_id 2500  library    0.00 ms ->  0.00 ms   0.97x

None of these ops is touched by the change, and all sit inside the drift the
baseline already documents for a repeat run (1.8% median, 9.9% worst). 104 of
the 117 are unchanged within +/-15%; the other 13 are the improvements above.

There *is* one real regression, and the sweep does not reach it — see "The
falsifier" in `../HANDOFF.md`. On a store with a large edge list and no
PROVISIONAL vertices the new `stale_provisional` costs ~23 ms where the old
one short-circuited in ~1.3 ms, because it always builds the adjacency. It is
bounded by the edge count and does not grow with store size.


--- Where the remaining time is -------------------------------------------

`dg check` is 21.6 s at 10,000 while `Graph.validate` is 3.1 s, so most of it
is no longer in `model.py`. A cProfile of `check.run()` at 5,000 vertices:

  2.43 s  cross.py:39      cross.evidence / rests_on -- scans every task,
                           once per decision id
  1.43 s  model.py:250     Graph.active_edge -- fix D's territory
  1.19 s  tasks.py:636,651 TaskGraph._out / _in -- scans every task edge,
                           once per task
  0.90 s  model.py:521     Graph.validate -- everything above, plus the rules

Same flat-list-scan shape as the fix just made, in two modules it did not
touch. That is where the next measurement should start.

`dgraph/server.py:113` calls `provisional_because` once per vertex for the
whole payload, which is the cubic shape `dg brief` had. `dg serve` was never
in the sweep, so this is unmeasured rather than known-slow -- but it is the
same call in the same shape, and `provisional_causes` is the fix if it bites.
